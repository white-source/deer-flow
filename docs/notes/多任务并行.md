现在全貌清楚了，这个限制来自前端和后端的双重保护：
     
  为什么不能输入第二个任务

  前端侧 — useStream hook（来自 @langchain/langgraph-sdk/react）在运行期间设置 thread.isLoading = true，InputBox 的提交按钮
  disabled={disabled}，直接阻止了重复提交。

  后端侧 — multitask_strategy 默认值为 reject，即便绕过前端限制发送请求，后端也会返回 HTTP 409。

  几种解决方案

  方案 1：改变 multitask_strategy（最简单，推荐）

  在 hooks.ts 的 thread.submit() 参数中加上 multitask_strategy: "interrupt"，新消息会中断前一个任务立即执行：

  await thread.submit(
    { messages: [...] },
    {
      threadId: threadId,
      multitask_strategy: "interrupt",  // ← 加上这行
      streamSubgraphs: true,
      ...
    },
  );

  同时前端需要允许在 thread.isLoading 时也能提交，而不是 disabled。

  方案 2：不同线程独立执行

  在 UI 上开多个聊天标签页，每个标签页对应不同 thread_id，互不干扰。这是框架原生支持的最佳方式。

  方案 3：在一个消息内并行执行（框架设计意图）

  利用子代理机制，在一个消息里让 LLM 分解任务并行执行，无需用户手动发第二条消息：

  用户: "帮我同时做三件事：查天气、读文件、写报告"
  → LLM 一次发出 3 个 task 调用，子代理并行执行
  → 收到所有结果后一次回复

  方案 4：enqueue（已实现）

  设置 ``multitask_strategy: "enqueue"``。同线程有 inflight run 时，新 run 进入 ``ThreadRunQueue``，HTTP 返回 ``202`` + ``queue_position``；前一个 run 结束后 ``RunDispatcher`` 自动启动下一个。前端在 ``thread.isLoading`` 时通过 ``submitEnqueuedRun`` 非阻塞入队。

  eerFlow 不是"一次只能执行一个任务"，它在多个层面支持并行，只是默认配置限制了同一线程内
  的并发。以下是各层面的并行能力：

  ---
  1. 子代理并行执行（框架内最直接的并行方式）
  
  LLM 一次可以发出多个 task 工具调用，子代理在后台并行执行，最多 3 个同时运行：

  LLM 一次响应:
    task("分析财报")   → SubagentExecutor → 线程池 worker 1
    task("搜索新闻")   → SubagentExecutor → 线程池 worker 2
    task("行情分析")   → SubagentExecutor → 线程池 worker 3
    # 3 个同时执行 → LLM 收到结果后汇总

  - 超过 3 个的 task 调用被 SubagentLimitMiddleware 截断（subagent_limit_middleware.py）
  - 提示词明确指导 LLM 将 >3 个任务分批执行
  - 通过 config.yaml 可调整限制范围 [2, 4]

  2. 不同线程独立执行

  不同 thread_id 的 run 完全独立互不干扰：

  # 线程 A 在执行
  curl -X POST /api/threads/thread-A/runs/stream -d '{"input": {...}}'

  # 线程 B 同时独立执行，不受 A 影响
  curl -X POST /api/threads/thread-B/runs/stream -d '{"input": {...}}'

  每个 thread 有独立的 Checkpointer、Sandbox、消息历史。

  3. 同一线程的多任务策略

  通过 multitask_strategy 参数控制：

  ┌────────────────┬──────────────────────────────────────────┬──────────────────────┐
  │      策略      │                   行为                   │       适用场景       │
  ├────────────────┼──────────────────────────────────────────┼──────────────────────┤
  │ reject（默认） │ 前一个 run 未完成时，新请求返回 HTTP 409 │ 防止误操作           │
  ├────────────────┼──────────────────────────────────────────┼──────────────────────┤
  │ interrupt      │ 中断前一个 run，立即执行新请求           │ 用户想重新开始       │
  ├────────────────┼──────────────────────────────────────────┼──────────────────────┤
  │ rollback       │ 中断前一个 run 并回滚 checkpoint         │ 用户想撤销之前的操作 │
  └────────────────┴──────────────────────────────────────────┴──────────────────────┘

  4. 多个工具调用并行

  LangGraph 的 ToolNode 会并行执行同一 LLM 响应中的所有工具调用：

  # LLM 一次返回多个工具调用
  tool_calls = [
      {"name": "bash", "args": {"command": "ls"}},
      {"name": "web_search", "args": {"query": "latest news"}},
      {"name": "read_file", "args": {"path": "/mnt/user-data/workspace/data.csv"}},
  ]
  # ToolNode 同时执行所有 3 个，结果一起返回给 LLM

  如何实现"同时执行多个任务"

  现有框架内最常见的做法

  通过子代理并行分解（提示词已内置支持）：

  用户: "帮我做三件事：写报告、查天气、总结邮件"

  LLM 思考: "这是三个独立任务，可以并行"
  → 一次发出 3 个 task 调用：
    task("写周报", subagent_type="general-purpose")
    task("查天气", subagent_type="general-purpose")
    task("总结邮件", subagent_type="general-purpose")
  → 3 个子代理同时执行
  → LLM 收到所有结果后汇总输出

  如果需要从外部同时触发多个任务

  1. 使用不同线程 — 每个任务开一个独立 thread（推荐）
  2. 使用 interrupt 策略 — 同一个 thread 上前一个任务被中断后立即执行新的
  3. 直接调用 DeerFlowClient — 嵌入式模式下可同时启动多个 client.stream()，每个有独立的 agent 实例

  可以改进的方向

  如果希望"同线程排队而不拒绝"，可以扩展 multitask_strategy 增加 enqueue 策略（当前定义了但未实现），让新 run 在前一个完成后自动开始。
